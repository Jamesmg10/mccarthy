# HiveMind Second Mind — PARA and CODE implementation

Prepared November 20, 2026. This is a bounded, local-first implementation authorized by the user's request to implement the Second Mind model and commit the workspace changes to main. It extends the workspace candidate from PR #4; it does not authorize browsing surveillance, new paid services, domain changes or claims that the complete course MVP is finished.

## Model and attribution

This is HiveMind's adaptation of Tiago Forte's organizational methods, not a neuroscience model or an endorsement from Forte Labs. PARA separates goal-oriented Projects, ongoing Areas, topic-oriented Resources and inactive Archives. CODE is Capture, Organize, Distill, Express. Sources, reopened November 20, 2026:

- https://fortelabs.com/blog/para/
- https://fortelabs.com/blog/basboverview/

Our implementation choices below are product design decisions. In this increment each source has one primary PARA collection, with an archive flag preserving that home. It is not a complete multi-project collection-management or automatic-classification system.

## User workflow

Capture: save the original URL, display title, why-saved note and existing retrieval-context label using the working Save Source form. New and legacy sources remain in Inbox until a user explicitly organizes them. Loading the app does not migrate or rewrite a library.

Organize: open Source Details, then choose Projects, Areas or Resources and name its collection in the Second Mind form. Use Purpose to describe a project's finish line, an area's responsibility or a resource's potential use. Existing `project` text remains unchanged for compatibility with current AI retrieval; it is not silently converted into a PARA category.

Distill: add a permitted excerpt, an explicit source locator, and your own takeaway. The source URL provides the parent reference; a nonblank excerpt requires a page/section/timestamp or similar locator. Text is user-supplied and not verified or generated by AI. Original notes are separate and unchanged. The Distill queue shows active sources without a takeaway; it is a convenience, not a mandatory sequence or cognitive assessment.

Express: choose 1–50 sources, write an optional synthesis and generate a Markdown brief containing the selected original URLs, saved notes, excerpt locations, takeaways and next-use notes. The brief is a local export, not a chatbot or AI synthesis. Draft prose is not automatically saved; users must download it. Changing inputs invalidates an old preview. The optional JSON backup exports the source records including Second Mind metadata; no import/restore feature is claimed.

## Routes and information architecture

The existing Library, Save Source, Source Details, Search Results and graph remain. Additional real destinations:

- `#mind`: Second Mind overview, CODE guidance and actual category counts.
- `#mind/inbox`: unfiled sources, including existing sources without supported metadata.
- `#mind/projects`, `#mind/areas`, `#mind/resources`: category views with exact collection filters.
- `#mind/archives`: inactive records with their original homes and notes preserved.
- `#mind/distill`: active sources without a personal takeaway.
- `#mind/express`: explicit source selection and brief export.

Archive/Restore is available in Source Details. It does not delete a record. Dirty note forms disable Archive/Restore until saved or discarded. All-source Library and Search can still retrieve archives, labeled as archived; category views isolate active records. The graph excludes archived records by default and offers an explicit include toggle.

## Graph semantics

The graph offers Saved project labels and Second Mind collections as separate grouping modes. Project mode preserves the original exact-label graph. PARA mode connects each source to its explicitly saved category plus collection. A Projects collection and an Areas collection with the same name are different nodes. The inspector shows the saved relationship basis. Unfiled records have no invented collection edge. No article agreement, topic similarity, or proactive discovery is inferred.

## Compatibility and privacy

The storage key stays `mccarthy-prototype-sources-v1`. Only an explicit Second Mind save adds or updates an optional `secondMind` object on that source. Existing `id`, `url`, `title`, `whySaved`, `project`, `createdAt` and unknown record fields are preserved. Version-1 metadata contains category, collection, purpose, excerpt, locator, takeaway, nextAction and archived, plus timestamps. Unknown fields within a valid version-1 object are preserved. Unsupported versions or malformed metadata block organization edits rather than being overwritten.

Writes use the existing compare-before-write guard. Corruption, changed snapshots and storage failures do not silently reset the library. Concurrent-tab guards are best-effort browser-local protection, not transactional database guarantees. No private real library was accessed in the tests.

Local word search includes supported Second Mind text with field-specific evidence. The unchanged OpenAI endpoint still receives only consented query, selected original notes and original project labels. PARA fields, takeaways and excerpts are not sent or embedded. New UI text makes that distinction explicit. The backend, model, cutoff, consent requirement, reviewer code, environment names and Netlify settings remain unchanged. No new dependencies or network requests are needed for Second Mind.

The static build now allowlists eight files: index.html, styles.css, app.js, ai-search.js, core.js, knowledge-graph.js, second-mind.js, second-mind-ui.js. No documentation, tests, server code or secrets enter dist.

## Verification and remaining gates

Run `npm run check`, `npm test`, `npm run build`, then `python tests/client_dom_check.py` and `python tests/second_mind_dom_check.py` when Playwright/Chromium are available. Use `CHROMIUM_PATH` for an existing Chromium executable. The Python harnesses are explicitly isolated tests with synthetic records and mocked storage/network; they do not make paid requests or certify hosted persistence.

Observed in this task: 58 Node tests pass (23 unchanged server fixtures, 16 workspace tests, 19 new Second Mind tests); 25 workspace browser checks and 18 Second Mind browser checks pass; 75 total measured route/width combinations have no horizontal overflow. Syntax/build pass. Browser-generated Markdown/JSON downloads were inspected. Full hosted browser-to-OpenAI testing, actual deployed-origin reload, independent reviewer testing and broad accessibility conformance remain separate release evidence. Existing user verification applies to the prior working prototype, not an automatic pass for every new screen.

Source-grounded AI summaries, Supabase persistence/authentication, semantic graph suggestions, automatic PARA categorization and collaborative memory are not implemented here. The manual takeaway does not satisfy a claim of AI source summarization. Merging main may trigger an already configured hosting pipeline; no deployment command or hosted-success claim is made by this work.

## Rollback

Revert only the Second Mind increment to return to the merged workspace. Do not clear browser storage or change the site's origin. Older workspace code ignores the additive fields and preserves unknown record properties during edits. Export a backup before any human rollback/data work.
